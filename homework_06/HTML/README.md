# Лекція 14 — HTML: дві кнопки, які вмикають світло за 3000 км

Найпростіша ланка з трьох — одна сторінка без збірки, без фреймворка, без
залежностей. Дві кнопки, `fetch()` до FastAPI і поле, куди чесно виводиться
відповідь сервера. Саме тут ланцюг «браузер → бекенд → хмара → пристрій»
починається.

Ця тека — перша ланка з трьох: **`HTML/`** → `FastAPI/` (бекенд) →
`ESP32/` (прошивка з підпискою на команди).

---

## Архітектура

```
┌──────────────────────────────┐
│  index.html                  │  один файл, відкривається подвійним кліком
│  [Увімкнути]  [Вимкнути]     │
└──────────────┬───────────────┘
               │ fetch POST http://localhost:8000/actuators/led
               │ Content-Type: application/json
               │ {"value":"on"}
               ▼
┌──────────────────────────────┐
│  FastAPI  :8000              │  202 Accepted
└──────────────┬───────────────┘
               │ publish → topic: iot-course/demo/commands/led
               ▼
        AWS IoT Core  →  ESP32  →  LED
```

Сторінка знає рівно одну адресу і рівно одне поле в JSON. Ні про AWS, ні про
MQTT, ні про пристрій вона не чула — і не повинна.

---

## Структура проєкту

```
index.html   — розмітка, стилі і скрипт в одному файлі
```

Все в одному файлі навмисно: немає збірки, немає `npm install`, немає теки
`node_modules` на 200 МБ заради двох кнопок. Файл відкривається подвійним
кліком і працює.

---

## Як запустити

1. Запустити бекенд (тека `FastAPI/`):

   ```powershell
   fastapi dev main.py          # або: uvicorn main:app --reload
   ```

2. Відкрити `index.html` подвійним кліком у браузері.
3. Натиснути **Увімкнути** — у полі нижче з'явиться `202` і тіло відповіді.
4. Дивитись на LED у Wokwi (тека `ESP32/`).

Сервер для самої сторінки не потрібен: вона статична, `file://` достатньо.
Це працює тільки тому, що на бекенді ввімкнено CORS — див. нижче.

## Як влаштований запит

```js
const res = await fetch('http://localhost:8000/actuators/led', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ value })
});
```

**`JSON.stringify({ value })`** — скорочення для `{ value: value }`. На виході
`{"value":"on"}` — рівно те, що чекає Pydantic-модель `LedCommand` на бекенді.
Помилитесь у назві поля — отримаєте `422` з поясненням, що саме не так.

**Заголовок `Content-Type` обов'язковий.** Без нього FastAPI не розпізнає тіло
як JSON. І саме він робить запит «непростим» для браузера — див. CORS.

**`await res.text()`, а не `res.json()`.** Читаємо тіло як текст і показуємо
як є. Якщо сервер віддасть `502` з HTML-сторінкою помилки замість JSON —
`res.json()` впаде з незрозумілим «Unexpected token», і справжня причина
загубиться. Текст покаже правду будь-якої форми.

**`res.status` виводимо завжди.** `fetch` не кидає виняток на `404`, `422` чи
`500` — для нього це успішна відповідь. У `catch` потрапляє тільки мережева
помилка: сервер не піднято, немає з'єднання, заблокував CORS. Тому статус
треба перевіряти руками, а не сподіватись на `try/catch`.

**`finally { buttons.disabled = false }`** — кнопки блокуються на час запиту й
розблоковуються завжди, навіть після помилки. Без `finally` перша ж невдала
спроба залишить сторінку назавжди мертвою.

## CORS — чому сторінка бачить помилку, а сервер бачить успіх

Сторінка відкрита як `file://`, API живе на `http://localhost:8000`. Для
браузера це **різні origin**, і він блокує відповідь — навіть якщо сервер її
чесно віддав.

Виглядає це так: у консолі браузера — «CORS policy», у логах uvicorn —
спокійний `200`. Обидві сторони кажуть правду. Запит **дійшов і виконався**,
браузер просто не віддав відповідь скрипту.

> CORS захищає **користувача браузера**, а не сервер. `curl` тих самих обмежень
> не має — тому «через curl працює, з кнопки ні» це не парадокс, а діагноз.

Лікується на бекенді (`FastAPI/main.py`), не тут — жодним рядком у цьому файлі
CORS обійти не можна. Деталі — у README теки `FastAPI/`.

## Troubleshooting

| Симптом | Куди дивитись |
|---|---|
| «Помилка мережі — команда не дійшла» | бекенд не запущений, або не той порт |
| У консолі браузера «CORS policy» | `CORSMiddleware` у `FastAPI/main.py` |
| `422` у полі відповіді | не те тіло запиту — має бути `{"value":"on"\|"off"}` |
| `502` у полі відповіді | бекенд живий, але не достукався до AWS IoT |
| `202`, але LED не реагує | бекенд свою роботу зробив — дивіться `ESP32/` |
| Кнопки залишились сірими | JS впав до `finally` — дивіться консоль браузера (F12) |
| Змінили файл, нічого не змінилось | кеш браузера — Ctrl+F5 |

## Ключові факти заняття

- Щоб керувати пристроєм у хмарі, фреймворк не потрібен: `fetch` і дві кнопки
- `fetch` **не кидає виняток** на 4xx/5xx — статус перевіряємо самі
- Читати тіло як `text()` надійніше за `json()`, коли форма відповіді не гарантована
- CORS — обмеження браузера. Помилка в консолі, а причина на сервері
- `Content-Type: application/json` робить запит непростим і вмикає preflight
- Кнопки блокуються на час запиту й розблоковуються у `finally` — інакше один
  збій вбиває сторінку

### Копни глибше (по бажанню)

- **Показувати стан LED** — `GET /sensors/latest` раз на кілька секунд замість «випустив і забув»
- **AbortController** — таймаут на `fetch`, щоб зависла мережа не тримала кнопки заблокованими
- **Роздати сторінку з FastAPI** (`StaticFiles`) — тоді origin спільний і CORS не потрібен взагалі
- **`localhost` vs `127.0.0.1`** — для браузера це різні origin, хоч і одна машина
