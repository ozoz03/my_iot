# job.json — документ роботи для OTA

## Що це

JSON, який AWS IoT Jobs доставить пристрою по MQTT. Пристрій розбере його
(`ota.cpp`, ArduinoJson) і дістане три поля: `operation`, `version`, `url`.

Файл кладеться **в той самий бакет S3**, що й прошивка. Консоль не дає
вписати документ руками — на сторінці створення роботи (Custom job → From file)
ти вказуєш S3 URL саме цього файлу.

## Що підставити

У полі `url`, всередині плейсхолдера, три речі мають бути ТВОЇ:

- `eu-north-1` — регіон бакета (у нас Стокгольм, лишається)
- `ТВІЙ-БАКЕТ` — точне ім'я бакета (напр. `iot-course-firmware-yehor`)
- `firmware_1_1.bin` — точне ім'я файлу прошивки в бакеті, **побуквенно**

У бакет заливається `.pio/build/esp32dev/firmware.bin` під цим іменем.
**Не `merged.bin`** — у ньому на початку bootloader, і записаний у слот
застосунку він робить слот непридатним.

## Як це працює

`${aws:iot:s3-presigned-url-v2:...}` — це НЕ посилання, а плейсхолдер.
Коли пристрій запитає документ, AWS:
1. вдягне presigning-роль
2. згенерує підписане посилання на цей конкретний файл
3. підставить його замість плейсхолдера
4. відправить пристрою вже готовий url

Пристрій качає по цьому посиланню по HTTPS. Посилання живе 60–3600 секунд.

## Presigning-роль — як створити

Це окрема IAM-роль, не Policy пристрою і не поле в цьому файлі. AWS IoT
Core приміряє її щоразу, коли пристрій просить документ роботи.

**Trust policy** (із захистом від confused deputy — звужено по
`aws:SourceAccount`/`aws:SourceArn`):

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": { "Service": "iot.amazonaws.com" },
      "Action": "sts:AssumeRole",
      "Condition": {
        "StringEquals": { "aws:SourceAccount": "<ACCOUNT_ID>" },
        "ArnLike": { "aws:SourceArn": "arn:aws:iot:eu-north-1:<ACCOUNT_ID>:job/*" }
      }
    }
  ]
}
```

**Permissions policy:**

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::<ТВІЙ-БАКЕТ>/*"
    }
  ]
}
```

**Де її підключити.** Роль **не** йде ні в `job.json`, ні в Policy
пристрою — її вказуєш окремо в параметрі `presignedUrlConfig.roleArn`
виклику `CreateJob` (у консолі — поле вибору IAM-ролі на кроці створення
Job, там же, де вказуєш сам job document).

Джерело: [Managing jobs — AWS IoT Core Developer Guide](https://docs.aws.amazon.com/iot/latest/developerguide/create-manage-jobs.html)

## Критичні дрібниці

- **`-v2`, не `-v1`.** v1 не підтримує versionId і по-іншому кодує адресу.
- **Поле `version` має відрізнятись від того, що зараз на пристрої.**
  На пристрої `1.0.0` → у роботі `1.1.0`. Якщо збігається — пристрій
  вирішить, що вже оновлений, і звітує SUCCEEDED, нічого не завантаживши.
- **`version` у job.json = `FIRMWARE_VERSION` у прошивці, яку ти залив.**
  Тобто прошивка в бакеті зібрана з `version.h`, де стоїть `1.1.0`,
  і в job.json теж `1.1.0`. Інакше пристрій оновиться, але не закриє роботу
  (версії не зійдуться) — і качатиме по колу.
- **`operation: "ota"`** наш власний рядок. AWS його не читає — його читає
  наш код. Можна назвати як завгодно, головне узгодити з `ota.cpp`.

## Типова помилка

Пристрій отримав url, качає — і HTTP 403. Причини по спаданню ймовірності:
1. неправильне ім'я бакета/файлу в плейсхолдері
2. presigning-роль не має `s3:GetObject` на цей бакет
3. посилання протухло (пристрій спав між отриманням і завантаженням)

## Робота вже закрита — нової не буде

`SUCCEEDED` і `FAILED` — кінцеві стани. Пристрій питає `$next`, а закрита
робота в чергу `$next` не потрапляє, скільки не перезавантажуй.

Хочете повторити демо — **створюйте нову роботу з новим jobId**. Це
найчастіша причина «все зламалось, пристрій більше нічого не качає»
після вдалого прогону.

## Поламаний образ качається по колу

Кожен `mqtt_connect()` питає роботу заново, тому ресет посеред оновлення
означає «качаємо те саме ще раз». Якщо образ у бакеті не завантажується
взагалі, пристрій ходитиме по цьому колу нескінченно.

Зупиняється це з боку хмари: скасувати роботу (Cancel job) або залити
в бакет справний образ. На пристрої обмеження спроб немає.
